  2. Services, images and initialization

  - Start order: postgres becomes healthy → migrate finishes → seed finishes →
    api passes /readyz → frontend starts. If any step fails, nothing after it
    starts.
  - Backend image: 14.6 MB compressed, Alpine, runs as a non-root user. It holds
    only the three binaries (/app/api, /app/migrate, /app/seed): no source, Go
    caches or test files.
  - Frontend image: 23 MB compressed. Node builds the app, then unprivileged
    nginx serves only the built files.
  - Hardening: containers are read-only with all capabilities dropped. Postgres
    and the API are not published to the host.
  - Initialization:
    - migrate does nothing when the schema is current and refuses a dirty schema
      rather than forcing it.
    - seed loads data only when the users table is empty and never runs -reset.
    - Data lives in the named volume pgdata, which is the only volume.
  - nginx:
    - Serves the app, so reloading or opening /campaigns/{id} works.
    - Proxies /api/ and exactly /readyz on the same origin, so no CORS is
      needed.
    - Finds the API by its service name at request time, not localhost.
    - Passes API responses and statuses through unchanged; only its own upstream
      failures become a plain-text 502.
    - Is SSE-safe (no buffering) and sets security headers including a CSP.

  8. Limitations and security notes

  - The database password defaults to composer in Compose. It's local-only (the
    database isn't published to the host) and can be changed with
    POSTGRES_PASSWORD.
  - If your shell exports ANTHROPIC_API_KEY, auto picks Anthropic, which isn't
    built until Slice 1b, so the API stops at startup. The README says to use
    LLM_PROVIDER=demo in that case.
  - The "last 30 days" counts shrink once real time is past the seed date of
    2026-11-01. The README explains how to seed with today's date on a fresh
    volume.
  - make smoke needs curl and python3 on the host.
  - nginx's own 502 and 413 responses are plain text, so the UI shows its
    generic error message for them.
  - A safety check blocked one combined shell command that included the reset
    target, so I never ran make reset-volumes. Its docker compose down -v is the
    same command I used directly for the fresh-volume test.
  - I left the stack running with 5 test campaigns (the browser one, a log probe
