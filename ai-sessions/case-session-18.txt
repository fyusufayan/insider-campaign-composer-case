  API contracts (ARCHITECTURE §11.6, §12.1, §13.1)

  - GET /stats: one consistent snapshot read from committed rows.
    - Per channel, the statuses add up to approved_total from the approval. If

    makes it terminal has committed. That covers worker completions, skips,
    finishes without a request, and rows the release or reaper ends as cancelled
    or failed. The API counts the queued rows its cancel transaction cancelled,
    so the two processes have to be summed. Retries and 429s never add to it.
  - Provider duration: the clock starts in provider.Client.SendGated before the
    request is built, and the observation is recorded after the request returns.
    Nothing new runs between the final gate and http.Client.Do, and no database
    call was added to the dispatch path.
  - Rate limited: counts every 429 response the worker receives.
  - Queue depth: every worker process runs one GROUP BY query every 5 s. After a
    successful sample all six series are set (missing combinations are 0).
    After a failed sample the series are removed rather than left stale, and
    there are none before the first sample.
  - LLM metrics: a wrapper around the selected LLM client (llm.Observe) records
    every provider request, including repair and truncation retries. Demo-mode
    calls are counted too.
  - Restarts: counters and histograms live in the process and start at 0.
    Nothing is rebuilt from the database, which Prometheus reads as a counter
    reset.

  3. Why the standard library and not the official client

  prometheus/client_golang isn't in the local module cache, and the TLS
  interception blocks downloading it. I didn't disable TLS or checksum
  verification, and added no other dependency. Instead platform/metrics (about
  490 lines including the metric definitions) implements text format 0.0.4:
  counters, gauges and histograms. ADR-026 records this as a deliberate
  trade-off. It is not equivalent to the official client: there are no Go
  runtime or process metrics, no summaries, exemplars or OpenMetrics.

  5. Security and cardinality

  - Fixed label values: every label has a set of allowed values declared up
    front. Anything else is recorded as other or dropped, so no request text or
    customer data can reach the output. Size is fixed: 46 series from the
    worker, 82 from the API.
  - No identifying data: no campaign, user, destination, idempotency key or
    message text appears. Tests and the live scrape check for this.
  - Formatting: help text and label values are escaped. The endpoint accepts
    only GET and HEAD and returns text/plain; version=0.0.4; charset=utf-8.
  - Bounded handler: it only reads memory, so it keeps answering while the
    database is down.
  - Not published: /metrics isn't on a host port. On :8000, /metrics only
    returns the app's HTML page from nginx.
