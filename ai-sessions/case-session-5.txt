  1. Safe SQL compilation                                                       
  Implement the compiler inside `backend/internal/segment/`.                    
  Requirements:                                                                 
                                                                                
  * Accept only a non-zero `segment.Validated` value.                           
  * Never accept raw JSON or unvalidated `Rule` as compiler input.              
  * Never generate SQL from arbitrary user or LLM-provided identifiers.         
  * SQL identifiers and expression templates must come exclusively from trusted 
  Go constants or registry-owned compiler definitions.                          
  * Every dynamic value must be a PostgreSQL bind parameter.                    
  * Use deterministic placeholder numbering and argument ordering.              
  * Support every allowed attribute, event and behavior predicate.              
  * Implement top-level match and shallow group composition exactly as          
  specified in ARCHITECTURE.md.                                                 
  * Do not introduce new DSL syntax.                                            
                                                                                
  An invalid or zero-valued compiler input must return a controlled error,      
  never a panic or unfiltered query.                                            
  2. Event predicates                                                           
  Implement correct event semantics with time windows and optional category     
  filters.                                                                      
  The following properties must hold:                                           
                                                                                
  * Users with no matching events have event count zero.                        
  * `count_lte: 0` is equivalent to `not_exists` when filters are identical.    
  * `count_gte: 1` is equivalent to `exists` when filters are identical.        
  * `count_gte: 0` matches every user, including users with no events.          
  * Avoid inner joins that accidentally remove zero-event users.                
  * Window boundaries and UTC time semantics must match the architecture.       
  * Count predicates must not multiply event counts because of joins.           
                                                                                
  Use PostgreSQL integration tests to verify these properties.                  
  3. Abandoned-cart predicate                                                   
  Implement the `abandoned_cart` behavior using the exact purchase-recovery and 
  time-window semantics defined in ARCHITECTURE.md.                             
  Test at least:                                                                
                                                                                
  * Cart event with no subsequent purchase.                                     
  * Cart event followed by a qualifying purchase.                               
  * Purchase before the cart event.                                             
  * Cart and purchase at the same timestamp.                                    
  * Cart and purchase in different categories.                                  
  * Cart events exactly at the window boundary.                                 
  * Multiple cart events belonging to one user.                                 
                                                                                
  Do not invent new business rules if the architecture already defines the      
  behavior.                                                                     
  4. Audience statistics                                                        
  Implement the audience query and its data types according to §6.5.            
  For each selected channel, produce a mutually exclusive partition in this     
  priority order:                                                               
                                                                                
  1. `no_contact`                                                               
  2. `no_consent`                                                               
  3. `eligible`                                                                 
                                                                                
  The invariant is:                                                             
  `eligible + no_consent + no_contact = matched_users`                          
  Also compute the reach partition for selected channels:                       
                                                                                
  * both                                                                        
  * sms_only                                                                    
  * email_only                                                                  
  * unreachable                                                                 
                                                                                
  The four reach counts must sum to matched_users.                              
  Report users and messages as distinct units; do not confuse people reached    
  with message volume.                                                          
  Missing consent rows always mean no consent.                                  
  An opted-out user must never be counted as eligible.                          
  A user without contact information must never be counted as eligible, even    
  when opted in.                                                                
  For empty selected channels, return the documented zero-message and           
  unreachable-audience behavior.                                                
  Ensure aggregate queries do not duplicate matched users when multiple cart    
  events, purchases or consent records exist.                                   
  5. Database query safety

          +tive_at` never satisfies a condition.

  2. Compiler API and safety boundaries

  segment.Compile(v Validated) (sql string, args []any, err error) returns
  SELECT u.id FROM users AS u WHERE (…).
  - One row per user. There are no joins; every event check is a correlated
    subquery.
  - Input. It only accepts a Validated, so raw JSON and an unvalidated Rule
    can't reach it. A zero value returns ErrNotValidated.
  - SQL text. All SQL comes from Go constants: attributeColumns, eventTables and
    a few fixed fragments. Every value is a typed bind parameter ($n::text,
    ::text[], ::integer, ::bigint).
  - Numbering. Placeholders are numbered in the order they appear, and the same
    rule always compiles to the same SQL and arguments.
  - Fails closed. If anything can't be compiled (a field/operator mismatch, an
    empty list, an empty rule, a bad window), it returns ErrUncompilable — never
    a panic and never an unfiltered query. A test covers 20 such forged rules.

  3. Event and abandoned-cart semantics

  - Windows are t >= now() - make_interval(days => $n): the edge is included and
    there is no upper limit.
  - Exists / not_exists use EXISTS / NOT EXISTS.
  - count_gte / count_lte use a scalar (SELECT count(*) …), so a user with no
    events counts as 0 and joins can't multiply counts. This gives count_lte 0 =
    not_exists, count_gte 1 = exists, and count_gte 0 = everyone.
  - Category filters never match a purchase whose category is NULL.
  - abandoned_cart(N): the user has a cart event in the window with no purchase
    at or after that cart event's timestamp.
    - Any purchase recovers the cart, whatever its category, because the
      architecture defines no category matching.
    - A purchase at the same instant also recovers it.
    - One unrecovered cart event is enough.

  4. Audience partition

  - One query. The compiled statement becomes a CTE. Each user is classified
    once per channel: 0 = no_contact, 1 = no_consent, 2 = eligible.
  - Consent rows. These are LEFT JOINs on the primary key, so a user can't be
    duplicated. A missing consent row counts as no consent, and a user with no
    phone or email is no_contact even if opted in.
  - Counts. The query returns the per-channel counts and a 2×2 eligibility
    cross-tab. Go then projects these onto the selected channels:
    - Two channels: the reach partition is both / sms_only / email_only /
      unreachable.
    - One channel: its eligible users are sms_only or email_only and everyone
      else is unreachable.
    - No channels: by_channel is {}, messages is 0, and unreachable equals
      matched_users.
  - Checks before returning. The raw counts must agree with each other, and
    AudienceStats.Check() verifies every identity. A violation returns
    ErrPartitionViolation and no statistics.
  - Transaction. Stats runs in a read-only transaction with SET LOCAL 
    statement_timeout = '5s'. ComputeAudienceStats(ctx, Querier, …) runs inside
    a transaction the caller already has, for the future prepare step.

  7. Limitations and deviations

  - Recorded clarifications, not design changes:
    - Group composition: the rule's match combines its top-level conditions and
      its groups, each group being one operand.
    - *_days_ago: whole elapsed days.
    - Age: whole years, by the current UTC date.
    - Window edge: included, with no upper limit.
  - Compile output: it returns a full SELECT u.id … statement, not a bare WHERE
    fragment, so the audience query (and later the prepare step) can wrap it
    unchanged.

    package exists yet. Later packages can import it.
  - Read-only mode is set by pgx.TxOptions{AccessMode: ReadOnly} and checked by
    code review; no test fails a write through Stats.

    operators share the same subquery filter, future events affect none of them.
  - abandoned_cart: a cart counts only if it falls in the window, now including
    AND c.occurred_at <= now(). A purchase recovers it only if p.purchased_at >=
    c.occurred_at AND p.purchased_at <= now().
  - *_days_ago:
    - The lte form adds AND col <= now(), so between gets it too.
    - The gte form (col <= now() − N days) already excluded future timestamps,
      because N ≥ 0.
    - NULL handling is unchanged.
