❯ We are continuing Smart Campaign Composer.                                    
  CP1–CP6 are complete, reviewed, tested and committed. Begin CP7 — Vue 3 +     
  TypeScript Frontend for Campaign Creation, AI Interpretation and Audience     
  Preview.                                                                      
  Follow CLAUDE.md and the finalized architecture and roadmap.                  
  Read the relevant frontend/UI sections of docs/ARCHITECTURE.md and CP7        
  requirements from docs/ROADMAP.md. Also inspect the actual CP6 HTTP DTOs,     
  handlers and error envelopes before writing frontend API types.               
  Implement the real working frontend, not mock screens.                        
  Objective                                                                     
  Build a polished, responsive Vue application supporting:                      
                                                                                
  1. Creating a campaign from a name and natural-language brief.                
  2. Calling the backend AI interpretation endpoint.                            
  3. Displaying the interpreted segment and explanation.                        
  4. Displaying live audience counts and consent/contact partitions.            
  5. Selecting SMS/email channels.                                              
  6. Restoring a saved campaign through its URL.                                
                                                                                
  Use the real CP6 API. No fake audience data.                                  
  1. Frontend foundation                                                        
  Use the finalized stack:                                                      
                                                                                
  * Vue 3, Composition API.                                                     
  * TypeScript with strict typechecking.                                        
  * Vite.                                                                       
  * The UI and styling approach from the architecture.                          
                                                                                
  Set up:                                                                       
                                                                                
  * Frontend application and package scripts.                                   
  * Vitest and Vue Testing Library or the testing setup recommended in the      
  architecture.                                                                 
  * Development API proxy to the Go backend.                                    
  * Sensible application structure with typed API client, components and        
  composables.                                                                  
                                                                                
  Avoid introducing large dependencies unless they solve a real requirement.    
  Keep package versions compatible with Node 22.                                
  2. UX and visual design                                                       
  Create a professional SaaS campaign-composer interface appropriate for an     
  Insider One take-home case.                                                   
  Visual direction:                                                             
                                                                                
  * Clean, modern B2B product styling.                                          
  * Strong typography and spacing.                                              
  * Clear hierarchy between campaign brief, AI interpretation, audience results 
  and channel selection.                                                        
  * Consistent cards, buttons, form inputs, feedback and loading states.        
  * Accessible contrast and keyboard interactions.                              
  * Responsive desktop and mobile layouts.                                      
                                                                                
  Prioritize clarity and a convincing end-to-end workflow over decorative       
  animations.                                                                   
  The user must always be able to distinguish:                                  
                                                                                
  * What they asked for.                                                        
  * What the AI understood.                                                     
  * Which targeting conditions are actually active.                             
  * How many users match.                                                       
  * How many messages are eligible by channel.                                  
                                                                                
  Do not present the demo interpreter as a live Claude model.                   
  3. Campaign creation                                                          
  Implement the documented `POST /api/v1/campaigns` contract.                   
  Provide:                                                                      
                                                                                
  * Campaign name.                                                              
  * Natural-language brief textarea.                                            
  * Frontend validation consistent with backend limits.                         
  * Inline validation errors.                                                   
  * Pending/disabled state while submitting.                                    
  * Success navigation to a stable URL containing the campaign ID.              
                                                                                
  The URL must support loading the campaign on refresh or direct navigation.    
  Avoid requiring a campaign-listing endpoint, which CP6 does not implement.    
  4. Interpretation workflow                                                    
  Use `POST /api/v1/campaigns/{id}/interpret`.                                  
  Show:                                                                         
                                                                                
  * Clear progress state.                                                       
  * Interpreted summary.                                                        
  * Active segment conditions in human-readable form.                           
  * Assumptions and unsupported information.                                    
  * Suggested/selected channels.                                                
  * Demo model identification and interpretation metadata where available.      
  * Content brief goal, tone, length and offer.                                 
                                                                                
  Build a small typed DSL presenter for the existing supported condition types. 
  It should understand top-level `all`/`any`, shallow groups,                   
  attribute/event/behavior conditions and normalized city names.                
  Never show an invented natural-language description that contradicts the      
  actual normalized rule. Provide a readable JSON view as a secondary           
  diagnostic option if helpful.                                                 
  Do not attempt to implement manual DSL editing in CP7.                        
  5. Audience dashboard                                                         
  Display the backend's actual statistics:                                      
                                                                                
  * Matched users.                                                              
  * Eligible SMS messages.                                                      
  * Eligible email messages.                                                    
  * Total eligible messages.                                                    
  * Per-channel `eligible`, `no_consent`, `no_contact`.                         
  * Reach partition: `both`, `sms_only`, `email_only`, `unreachable`.           
  * Evaluation timestamp.                                                       
                                                                                
  Use understandable labels and distinguish users from messages.                
  Ensure these identities remain visually clear:                                
                                                                                
  * For each selected channel: eligible + no_consent + no_contact =             
  matched_users.                                                                
  * Both + sms_only + email_only + unreachable = matched_users.                 
                                                                                
  When the selected channel list is empty, show zero messages and explain that  
  no delivery channels are selected. Do not interpret zero selected channels as 
  zero matching users.                                                          
  Audience preview is live and informational: no approval or send action exists 
  in CP7.                                                                       
  6. Channel selection and concurrency                                          
  Use the exact `PUT /api/v1/campaigns/{id}/channels` contract:                 
  `{ "channels": ["sms", "email"], "expected_version": N }`                     
  Requirements:                                                                 
                                                                                
  * Explicitly support selecting neither channel.                               
  * Use the current campaign version in updates.                                
  * Use the response's new version after successful updates.                    
  * Refresh audience statistics after a successful channel change.              
  * Handle `409 version_conflict` by showing a clear message and offering to    
  reload the latest campaign.                                                   
  * Do not overwrite user choices using subsequent AI suggestions.              
  * Do not silently retry stale writes.                                         
  * Prevent accidental duplicate submissions while a mutation is pending.       
                                                                                
  7. Robust API error handling                                                  
  Implement a typed client for CP6 responses, including:                        
                                                                                
  * `422 validation_failed`                                                     
  * `422 invalid_brief`                                                         
  * `422 ai_output_invalid`                                                     
  * `422 llm_refused`                                                           
  * `409 version_conflict`                                                      
  * `409 invalid_state`                                                         
  * `503 llm_unavailable`                                                       
  * `503 audience_unavailable`                                                  
  * `502 llm_truncated` / `llm_rejected`                                        
  * Network errors and aborts.                                                  
                                                                                
  Especially important:                                                         
                                                                                
  * If interpretation succeeds but the response contains `audience_error`,      
  explain that the interpretation WAS SAVED and only the preview failed.        
  * Offer a separate retry for `GET /audience`, not a duplicate interpretation. 
  * Render all untrusted text as escaped plain text.                            
  * Never use `v-html` or unsafe innerHTML for briefs, model output or          
  `raw_proposal`.                                                               
  * Put `raw_proposal` behind a collapsed, clearly labeled diagnostic detail    
  section, not the main UI.                                                     
  * Never show raw secrets, database URLs or internal stack traces.             
                                                                                
  8. State management and async correctness                                     
  Keep state management small and idiomatic.                                    
  Account for:                                                                  
                                                                                
  * Loading a campaign from a URL.                                              
  * Creating a campaign.                                                        
  * Interpreting a campaign.                                                    
  * Updating channels.                                                          
  * Refreshing audience.                                                        
  * HTTP errors.                                                                
  * Stale async responses.                                                      
  * Unmounting or navigating while requests are pending.                        
                                                                                
  Avoid race conditions where an older audience response overwrites newer       
  channel selections or campaign versions.                                      
  Use AbortController or an equivalent request-epoch strategy.                  
  No global state library is required unless justified.                         
  9. Tests                                                                      
  Write meaningful frontend tests using mocked HTTP responses, not mocked       
  business logic.                                                               
  Cover:                                                                        
                                                                                
  1. Create campaign → navigate to detail.                                      
  2. Load a saved campaign by ID.                                               
  3. Valid interpretation renders its summary, segment and real-shaped audience 
  statistics.                                                                   
  4. Initial suggested channels are shown.                                      
  5. User deselects all channels → update sends `[]`, then audience refresh     
  shows zero messages and preserved matched users.                              
  6. `409 version_conflict` → reload latest state without silently overwriting  
  a user edit.                                                                  
  7. `invalid_brief` with field-level details.                                  
  8. AI refusal and unavailable provider.                                       
  9. Interpretation persisted but audience unavailable.                         
  10. `raw_proposal` containing HTML or script-looking text is displayed        
  safely.                                                                       
  11. All groups and condition types render correctly.                          
  12. Out-of-order async results do not overwrite newer state.                  
  13. Keyboard and form validation basics.                                      
                                                                                
  Add at least one integration-level frontend test for the full create →        
  interpret → select channels workflow.                                         
  10. Backend compatibility and docs                                            
  Inspect the actual API DTO fields and use their exact JSON names and types.   
  Do not invent fields or routes.                                               
  If the frontend exposes a genuine API-contract gap, report it before          
  expanding the backend. Favor adapting the frontend to the documented CP6

  Add a short frontend development section to README or the appropriate

  Record the already implemented CP6 API clarifications in the appropriate

  convenience.

  Do not implement:                                                             
                                                                                
  * CP8 Docker Compose integration.                                             
  * Content generation or live content streaming.                               
  * Approval/confirm/send buttons.                                              
  * Delivery dashboard or worker.                                               
  * Mock provider.

  Do not modify backend persistence or migration semantics without a
