  Issue: Which channels a campaign has after interpretation. campaigns.channels
  defaults to '{}', and audience statistics are computed only "for each

  Recommendation: Interpret sets channels := suggested_channels only while 
  channels is still empty. After that, only PUT /channels changes them.
  ────────────────────────────────────────
  #: Q2
  Issue: "A scripted invalid rule produces field-level errors visible in the 
  UI."
  The documents say scripted is for tests only and the running app uses only
  demo (§7.3, ADR-016).
  Impact: The two rules conflict, so I can't meet this criterion literally
  without bending one of them.
  Recommendation: (a) Prove the backend half in an API integration test with
  scripted: 422 ai_output_invalid, field-level details, and a query tracer
  showing no SQL ran against the user tables. (b) Prove the UI half with a
  Vitest test that feeds that same 422 response into the error component. I
  would not add a "bad output" keyword to the demo LLM.
  ────────────────────────────────────────
  #: Q3
  Issue: The content_brief schema ({goal, tone, length, offer}) has no field
  types or allowed values defined anywhere. The only hint is the example in
  §6.2.
  Impact: The structured-output schema and the strict decoder can't be written
  without it.

  characters; tone: string up to 32; length: short | medium | long; offer:
  {kind: none | percent_discount | amount_discount |  free_shipping, value?}

  subset of {sms, email}, and assumptions/unsupported allow up to 10 strings of

  ────────────────────────────────────────

  city_normalized is "Turkish-aware folded", and the validator needs a "known
  city" list. Neither the folding rules nor the list's source is defined.
  Impact: Seed data, validator and compiler must all use the same function, or
  the counts won't match.

  istanbul → İstanbul), used by the seed, the validator and the prompt catalog.

   collapse spaces. That way Istanbul, İSTANBUL and istanbul all become
  istanbul.

  4. Deterministic seed

  - Inputs: SEED_USERS (default 5000), SEED_RANDOM_SEED (default 42), and
    SEED_REFERENCE_TIME, an RFC 3339 UTC timestamp. I suggest the default
    2026-11-01T00:00:00Z. Override with an environment variable, e.g.
    SEED_REFERENCE_TIME=2026-12-01T00:00:00Z make seed. Compose passes it
    through as ${SEED_REFERENCE_TIME:-2026-11-01T00:00:00Z}.
  - Generation:
    - Random numbers come from math/rand/v2 PCG seeded from SEED_RANDOM_SEED and
      a fixed stream constant, drawn in a fixed order. There is no map
      iteration and no clock reads.
    - Every timestamp is the reference time minus a random offset, truncated to
      microseconds to match PostgreSQL. That covers signup_at, last_active_at,
      birth_date, cart and purchase times over the 90 days before the reference
      time, and channel_consents.updated_at, which is written explicitly instead
      of defaulting to now().
    - Rows are inserted in generation order with CopyFrom into tables with
      freshly reset sequences, so IDs are deterministic too.
  - Same inputs give the same dataset: checked by a unit-test hash over a
    canonical serialization, and by an integration test comparing the rows read
    back from the database.
  - Re-run policy:
    - A plain run does nothing if users is populated.
    - -reset runs in one transaction: it aborts if any campaign_deliveries row
      exists, then deletes customer data, restarts the sequences and reloads. It
      never uses TRUNCATE … CASCADE, which could delete delivery rows and break
      invariant 6.
    - The seed logs the inputs it used, so any dataset can be reproduced.

  5. Unresolved decisions

  U1 — amount_discount currency. The type and precision are supported by the
  documents; the currency is not. Options:
  - (a, recommended) Drop amount_discount from the v1 enum. offer.kind becomes
    none | percent_discount | free_shipping. A fixed-amount request then goes
    into assumptions and the offer is set to none. This adds no rule and can be
    added back with an ADR.
  - (b) Keep it and add a required currency field (ISO 4217 code, or a fixed
    allowed list). Value: decimal, ≤2 fractional digits, > 0, ≤
    9,999,999,999.99. This would need a short ADR.
  - Also confirm that percent_discount is an integer.

  U2 — Fixed reference time vs. demo data aging. Segment queries use the
  database now() (§6.4; I'm not changing that). Seed data spans the 90 days
  before a fixed reference time. So as real time moves past it, "last 30 days"
  queries match less data. About 30 days after the reference time, the example
  brief matches 0 users, and the Slice 1a acceptance criterion fails for anyone
  running docker compose up later, such as a reviewer. Options:
  - (a, recommended) Keep the fixed default; it is what the tests use, and they
    don't depend on the default anyway. Add make seed-today, which passes
    today's UTC midnight as the reference time. Document in the README that
    demos run long after the default should use it, and that the inputs logged
    by the seed reproduce any dataset.
  - (b) Keep the fixed default and pick a value far enough ahead that it covers
    the review period. Timestamps in the future would be filtered out by the
    window logic, so this distorts the data.
  - (c) Accept the decay and only document it.

  Minor confirmations (I'll proceed this way unless you object):
  - PUT /channels accepts an empty list. The audience then reports zero messages
    and every user as unreachable. Prepare (Slice 3) enforces at least one
    channel.
  - percent_discount is an integer (see U1).

  2. Implementation decisions

  - Provider resolution is a pure table in config; main refuses Anthropic. If
    the resolved provider is anthropic (explicit, or auto with a key set), the
    API exits with "not available in this build". It never falls back to demo.
    CP5/1b replaces this check with the real client.
  - Two-layer masking. The Phone/Email types are the intended way to log contact
    data. As a backstop, every logged message, string field and error message
    is scanned for emails and phone numbers. Phone numbers are only recognized
    with a leading +, so IDs and timestamps are left alone. Other value types
    logged as raw objects are not scanned; the explicit types cover those.
  - Request IDs: a client-supplied X-Request-ID is reused only if it is up to 64
    characters of [A-Za-z0-9._-]. Otherwise a fresh 128-bit hex ID is
    generated. This prevents log and header injection.
  - Middleware order: request ID → access log → panic recovery → routes. A
    recovered panic therefore shows up in the access log as a 500.
    http.ErrAbortHandler is re-raised as Go's HTTP server expects. If the
    response has already started, nothing more is written. The panic text and
    stack go to the log, never the response.
  - The access log records the path only. Query strings are left out because
    they may carry user data. The response wrapper still allows flushing, which
    the SSE streams in later slices need.
  - The server has no write timeout, because SSE responses are long-lived.
    Header read timeout is 5 s, idle timeout 120 s, shutdown waits up to 10 s.
  - Nothing logs the database URL or the API key. Connection errors from the
    driver mask the password, and a test checks this.

  6. Deviations

  - Error codes: I added internal (500) and method_not_allowed (405), which are
    not in the §11 list, so every response uses the envelope. If you'd rather
    extend §11, that's a one-line documentation change.
  - Config scope: CLAUDE_SEGMENT_* moves to CP5 and SEED_* to CP2, where they're
    first used. This avoids validating settings nothing reads yet. The
    provider-selection settings are already done.
  - Makefile targets: up, seed and seed-today are not added yet. They depend on
    Compose and the seed generator, so they land in CP2/CP8. make test-frontend
    skips until frontend/ exists.
  - Request ID inside a group: if code calls logger.WithGroup(...), the
    request_id field ends up nested inside that group. Nothing uses groups yet.
  - No changes to the four design documents or ai-sessions/. git status shows
    only the new backend/, Makefile, .gitignore and .env.example.
